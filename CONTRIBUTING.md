# Contributing

Thanks for improving the toolkit. Keep it practical.

## What makes a good pull request

- A template, checklist or question that you have **actually used** in a ceremony,
  sprint or interview loop
- Named ceremony and team size it works for (a 5-person team's planning agenda is not
  a 30-person ART agenda)
- Short: if it needs a page of preamble, it belongs in a blog post, not a template

## What will be closed

- Marketing content, course promotions or link insertions
- Restating the Scrum Guide with new headings
- Vendor-specific tool instructions that lock the template to one product

## Style

- Markdown, `##` for sections, tables for agendas and options
- Checklists use `- [ ]`
- Indian and global contexts both welcome; state currency and timezone when it matters
- British or American spelling is fine — match the file you are editing

## Process

1. Open an issue describing the gap and the ceremony it affects
2. Fork, branch, edit one file per pull request
3. Describe what changed and where you used it
4. One maintainer review; merge is usually within a week
